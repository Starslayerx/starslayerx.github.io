Using EXPLAIN

Source Postgres 为收到的每条查询制定查询计划 (query plan)，要获得良好的性能，选择和查询结构 (query structure) 和数据特征 (properties of the data) 想匹配的正确计划至关重要，因此系统内置了一个复杂的规划器 planner。 可以使用 EXPLAIN 命令查看规划器生成的查询计划，本篇文章介绍相关知识。 EXPLAIN Basics 查询计划的结构是一个查询节点的树 (tree of plan nodes)。 树的底层节点是扫描节点 (scan nodes)，它们从表中返回原始行。 对于不同的表访问方式，有不同的扫描节点类型：顺序扫描，索引扫描和 bitmap 位图索引扫描。 也有非表行来源，例如 VALUES 子句和 FROM 中的集合返回函数，他们各自有对应的扫描节点类型。 如果查询有 joining 连接，aggregation 聚合， sorting 排序 或其他操作，则扫描节点上面会有额外的节点来执行这些操作。 通常会有不止一个方法来执行这些操作，因此这里会出现不同类型的节点类型。 EXPLAIN 的输出会为计划树中的每个节点各显示一行，展示该节点的基本类型，以及规划器对该节点执行时所作的代价估算。 可能会出现一些附加行，它们相对于节点的摘要进行缩进，用来显示该节点的其他属性。 第一行是估计的计划总执行代价 (estimated total execution cost); 这是规划器尝试减小的数字。 例如： EXPLAIN SELECT * FROM tenk1; QUERY PLAN ------------------------------------------------------------- Seq Scan on tenk1 (cost=0.00..445.00 rows=10000 width=244) 由于该查询没有 WHERE 语句，因此规划器选择了单次的顺序扫描计划。 ...
